# v0.7.1 Delta Audit Response

This response records the disposition of the independent v0.7.0 delta audit.
It does not include machine names, account identifiers, task IDs, local paths,
private source, rollout content, commands, or credentials.

## Confirmed bugs fixed

- Working-tree Git fingerprints could invoke configured clean or process
  filters. Governor now uses bounded raw file reads and safe metadata primitives;
  the regression includes a filter that would create a marker if executed.
- Version-3 write leases could retain an active lifecycle. State version 4
  quarantines them and permits only explicit coordinator release or retirement.
- Partial SQLite queries could end as healthy. Availability is now `full`,
  `partial`, or `unavailable`; partial coverage is at least a warning.
- Exact untimestamped rollout duplicates were not deduplicated per file.
- Cache-write coverage could look fully observed when only some selected files
  exposed the field.
- Approval retries with regenerated correlation IDs could evade the persistence
  postcondition despite structural equivalence.
- Missing spawn fields could be treated as V1 full-context defaults without a
  recognized V1 schema. V1, V2, and unknown are now separate observations.
- Rule discovery was regex-first, limited per file, and could report healthy
  after incomplete parsing. It is now lexical, globally capped, and partial
  coverage cannot be healthy.
- Inspector readers did not uniformly prove containment beneath the canonical
  Codex root. Every reader now rejects escaped reparse paths.
- Session discovery truncated by traversal order and could miss an older task
  resumed today. Chronos now inventories all session partitions within a
  three-second traversal budget, filters on recent modification time, retains
  the eight newest eligible files, and reports an inventory timeout explicitly.
- Oversized rollout heads could hide unavailable metadata while task age looked
  precise. Head truncation and age coverage are explicit.
- Issued plans did not reserve concurrency. Pending plans now consume the same
  bounded capacity budget as active leases.
- Expired verified read leases could become difficult to clear. Explicit
  coordinator release is accepted after expiry.
- The release builder materialized content before enforcing package size.
  File-count, per-file, and total byte limits now run first and are recorded in
  the release manifest.
- Ordinary CI used a mutable checkout tag and fewer validation gates. It now
  pins checkout, uses two Windows runner labels, applies a timeout, and parses
  every PowerShell and JSON source before tests.

## Heuristic and tuning issues

No warning threshold, critical threshold, scoring weight, or predictive
heuristic changed. Process ownership remains name-based and is now explicitly
labeled `executable_name_only_unverified`. Filesystem-helper diagnosis remains
limited to known markers and is labeled `known_markers_15m`. Broader ownership
and marker inference require labeled field evidence and belong in a separate
calibration release.

## Feature and UX improvements

- GitHub positioning now describes the full diagnostic and coordination scope.
- Exact install commands appear in the first README viewport.
- A synthetic, sanitized 9:16 proof card and 1280x640 social preview show why
  machine health and workflow diagnostics must remain separate.
- The plugin manifest exposes the proof screenshot and current search keywords.
- A privacy-gated issue form prevents accidental attachment of local diagnostic
  files and identifiers.
- The OpenAI Plugin Directory listing copy, assets, reviewer prompts, and
  evidence links are prepared in one submission packet.
- GitHub About, website, and discovery topics were updated independently of the
  release so search indexing can begin immediately.

## Validation boundary

The deterministic suites validate modeled behavior on the development Windows
machine. v0.7.1 is not called field-validated until another installation machine
successfully exercises the released plugin and reports the result.
