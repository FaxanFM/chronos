# v0.8.6 Full Audit Response

This record maps the independent post-release v0.8.6 findings to the focused
v0.8.7 engineering candidate. The immutable v0.8.6 GitHub and OpenAI Plugin
Directory releases remain historical records. v0.8.7 is not validated or
published until local, CI, independent-review, and external Windows canary
gates pass.

## High Findings

| Finding | v0.8.7 disposition | Deterministic evidence |
| --- | --- | --- |
| Interpreter option values appeared safely constrained | Fixed with conservative interpreter-specific operand parsing; only recognized fixed execution operands qualify | Five option-value false-safe cases plus PowerShell `-File` negative control |
| Host inventory could rewind lifecycle time or rank | Fixed: every mutation uses timestamp/rank ordering and rejected input preserves clocks and revision | Older inventory and equal-timestamp lower-rank regressions |
| Global mutex could silently fall back to Local | Fixed: shared supervision state fails closed when the Global mutex is unavailable | Static namespace contract plus live contention and fallback-queue tests |
| Task generation was discarded or coalesced | Fixed: supervision persists generation; Heartbeat baselines, conditions, recovery, and interventions bind compatible generation | Same ID/new generation produces a distinct condition and intervention |
| Planned or claimed interventions were not resumable | Fixed: one Governor can list bounded active records and reclaim an expired claim without raw task IDs | Restart list, claim persistence, expiry, and reclaim tests |
| Public verification accepted the wrong state or internal engine identity | Fixed: only `verification_pending` or `active_violation` accepts allowlisted host evidence; internal recovery remains cycle-only | Queued, claimed, and public-engine rejection plus valid native recovery |
| Governor state lacked reparse and hard-link containment | Fixed with canonical root checks, reparse-ancestor rejection, final-directory checks, and leaf link-count enforcement | Reparse parent, hard link, path escape, and normal write tests |

## Unchanged Boundaries

v0.8.7 does not change warning or critical thresholds, scoring weights,
predictive claims, model pricing claims, shared-folder write delegation, or the
one-Governor topology. Chronos creates no OS scheduled task, daemon, service,
publisher telemetry, or persistent diagnostic log. Host task and automation
tools remain the authority for liveness, recurrence, transport, and model-role
verification.

## Independent Remediation Re-review

The second independent review identified six additional release blockers. The
same v0.8.7 candidate line now closes them before external canary handoff.

| Finding | v0.8.7 disposition | Deterministic evidence |
| --- | --- | --- |
| A fixed `curl` URL prefix allowed an additional positional URL | Fixed: `curl` prefixes remain broad because later operands can change the destination | Structured-rule regression with a credential-shaped `curl` prefix |
| JSON encoded inside `function_call.arguments` bypassed strict parsing | Fixed: JSON-looking nested argument strings must pass the duplicate-key and case-collision parser before deserialization | Nested duplicate-key rollout record increments malformed coverage and cannot affect approval accounting |
| An outbox event could be planned against a replacement task generation | Fixed: events with observed generation evidence bind its hash through the outbox and planning fails closed on mismatch | Generation G1 event followed by G2 observation returns `target_generation_mismatch` |
| Schema-6 interventions migrated to an unreachable synthetic Governor | Fixed: unsent records migrate to an explicit unassigned owner and can be adopted only after target and generation verification; ambiguous claimed sends remain visible | Queued migration claim plus claimed-send `delivery_unknown` migration tests |
| An expired send claim could be retried after an unknown transport outcome | Fixed: expiry enters `delivery_unknown`; only a definite transport failure can consume the single retry | Expired-claim reclaim rejects a second claim and requires reconciliation without retry |
| Heartbeat and plugin documentation contained stale scope, schema, and version text | Fixed: default scope is machine plus Codex home, state schema is 7, and plugin documentation describes current controls | Release documentation and package consistency checks |

The replacement review found three further compatibility defects. The current
candidate discovers the v0.8.6 CWD-derived default namespace for the active
working directory, imports and upgrades it without writing the source, and
persists the rebound scope only at the stable destination. Intervention events
now carry distinct subject and owner generation hashes. Owner-targeted planning
uses `ownerGeneration`, and fails closed when subject generation is known but
the distinct owner's generation is unavailable. Deterministic tests preserve
the prior file hash and timestamp and cover truthful and stale owner generations.
Corrected or rotated owner-generation evidence now replaces the stale pending
Governor envelope and re-arms the same open condition with a new event identity;
no monitored task is contacted before replacement planning succeeds.
